## Refactor Boundary

`db/migrations` is schema-evolution and database-contract infrastructure. It is not a runtime domain module.

Migration behavior must preserve applied-schema compatibility unless an explicit owner authorizes rewrite, squash, reset, or rebaseline.

Boundaries:

- Authored migrations: `db/migrations/00001...00040_*.sql`
- Embedded source: `db/migrations/source.go` embeds `*.sql` and exposes `dbmigrations.Source()`
- Generated SQL/code: `internal/gen/sql/*`, downstream of `sqlc.yaml`, `db/migrations`, and `db/queries`
- Queries: `db/queries/*.sql`, authored sqlc inputs
- Fixtures/tests: pgtest template databases, migration scratch databases, pgschema hash, backend store/integration tests
- Bookkeeping: `goose_db_version`, created by goose at runtime, not authored SQL

Migration status classification:

- Historical authored migration history: all numbered files `00001` through `00039`
- Current forward repair migration: `00040_incident_metadata_canonicalization.sql`
- Phase-shaped historical names: `00001` through `00033`, plus `00035`
- Non-phase-shaped active/post-phase names: `00034`, `00036`, `00037`, `00038`, `00039`, `00040`
- Active development-only: none proven by repository evidence; no numbered migration may be treated as development-only from this checkout alone
- Applied/shared: blocked on external live or retained `goose_db_version` evidence; treat all numbered migrations as potentially shared/applied

## Target-Specific Invariants

- Migration ordering and numbering: filenames must start with a numeric goose prefix like `00009_name.sql`; `scripts/check-migrations.sh` validates numeric prefixes and sorts files lexically. Do not renumber existing files without explicit rebaseline authority.
- Direction policy: every SQL migration has `-- +goose Up` and `-- +goose Down`; no repository-wide no-down policy was found. Down migrations are not proof of safe production rollback.
- Idempotency: goose provides applied-version gating. Some DDL uses `IF NOT EXISTS`, and the phase 0 support test requires rerun-safe bootstrap DDL, but no global rerun-idempotency policy was found.
- Drift/checksum: no checksum table or checksum enforcement was found. Drift controls are `migration-input-drift`, `migration-scratch-apply`, `migration-drift`, sqlc `generate-drift`, and the pgtest schema hash.
- Applied immutability: assume existing numbered migrations are immutable until owner policy says otherwise.
- Module ownership: every table/view/function/index/constraint must map to a Cartulary owner in `tools/schema_object_ownership_manifest.json`.
- Generated files: never hand-edit `internal/gen/sql/*` or other generated roots declared in `tools/generated_artifact_policy.json`.
- sqlc compatibility: any schema/query change must preserve `sqlc.yaml` inputs or regenerate through `make generate` and verify with `make generate-drift`.
- Fixture compatibility: changing migration bytes changes `internal/testutil/pgschema.Hash()` and template DB identity.
- Rollback/restore/recovery: restore preflight reads `goose_db_version`; recovery tables and backup metadata must remain compatible with restore verification.
- Extension-profile schema boundaries: optional artifact surfaces remain `links`/`projections`; snapshot reporting is `reporting`; reference packs are `reference_data`; enterprise authentication is `auth`; incident bundle portability is `incidentbundles`. These owners do not make extension-profile schema part of the Base Profile.
