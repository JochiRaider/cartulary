# Entities Module Refactoring Tracker and Handoff

## 1. Scope and Source Posture

Target directory: `internal/modules/entities`.

This file began as a planning-only tracker. A follow-on remediation task was later authorized and implemented. The tracker now records the post-remediation state, the remaining remediation plan, and handoff status. Generated roots and generated phase ledgers remain downstream artifacts and must not be hand-edited.

Allowed changes for this remediation session:

- Move ownership boundaries when the durable owner is clear.
- Preserve Core-owned public routes, request/response envelopes, idempotency, authorization outcomes, revision behavior, projection refresh behavior, WebSocket publication semantics, and harness accounting.
- Add characterization and boundary guard tests under Make-owned validation.
- Update owner docs and authored contract inputs when ownership changes.

Non-goals:

- Do not treat `internal/modules/entities` as a permanent module boundary merely because the directory exists.
- Do not hand-edit generated roots, generated phase ledgers, or tool-managed artifacts.
- Do not keep internal compatibility shims unless they provide clear continuing value.
- Do not treat phase maps, test rows, prior plans, or this tracker as runtime architecture.

Source hierarchy for this tracker:

1. Adopted subsystem NLSpecs for their named subsystem only.
2. Core 00 through Core 04 for implementation-conformance behavior.
3. Core 05 only for claim-bearing timed or fixture-sensitive publication.
4. `docs/domain.md`, `docs/testing-harness-nlspec.md`, `docs/design.md`, and implementation-support guides for vocabulary, boundaries, harness mechanics, and execution support.
5. Current repository code and tests for current implementation state.
6. Prior plans and framework files as evidence, not authority.

Architectural finding: `internal/modules/entities` is still mixed, but less so after this remediation. It now owns host/identity entity-domain behavior, entity mention policy, and explicit entity merge policy. Indicator runtime logic moved to `internal/modules/indicators`; timeline row snapshots moved to `internal/modules/timeline/rowsnapshot`; generic workbook row-create route registration moved to `internal/modules/workbook`. Remaining high-risk coupling is concentrated in mention and merge side effects across links, assessments, revisions, projections, timeline source-row updates, and collaboration publication.

No `BLOCKED: owner contradiction` item is recorded. Repo/framework mismatches were treated as findings and remediated where the target owner was clear.
