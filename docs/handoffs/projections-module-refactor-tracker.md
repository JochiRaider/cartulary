## 3. Workbook Boundary Diagnosis

The current `internal/modules/workbook` package is a mixture: it is a transport-adjacent application facade for workbook routes, query pagination, authorization rechecks, mutation request decoding, row refresh responses, and collaboration publication, while still coordinating source-owner facades, revisions, links, and projection refreshes. For projection-backed surfaces it has already become thinner: `Store.QueryRows` dispatches timeline and entity-owned query paths and delegates generic projection surfaces to `projections.Store`.

`internal/modules/projections` is not itself the workbook package. The projection package currently acts as a derived-read-model and projection-query facade with cross-domain rebuild/refresh orchestration. That is legitimate current behavior, and Q-002 now closes the permanent boundary question with a hybrid provider decision: keep workbook query semantics, row serialization, filter/sort/group/cursor behavior, rebuild orchestration, provider registry, and telemetry in the projections facade; move source-domain-specific row-derivation SQL behind source-owner projection providers incrementally.

### Q-002 Closure: Hybrid Provider Boundary

Q-002 is architecturally closed. Source-domain-specific projection SQL must move incrementally into source-owner projection providers, but only behind a stable `projections` facade. This is not a move-everything-out decision. The facade remains responsible for workbook query semantics, `view_row_v1` row serialization, field/cell/group/query wire shape, generic sort/filter/group/cursor behavior, refresh and rebuild orchestration, restore compatibility, provider registration, and projection telemetry. Providers own the domain-specific SQL that derives projection rows from authoritative source tables.

Provider descriptor contract:

| Descriptor field | Required rule |
| --- | --- |
| `provider_key` | Stable internal token, unique across providers. |
| `source_owner_key` | Logical owner of authoritative source-state semantics. |
| `view_schema_ids[]` | Non-empty list of exact standardized `view_schema_id` values handled by the provider. |
| `source_record_types[]` | Exact source record types read as authoritative state. |
| `projection_table_families[]` | Projection table families or equivalent read-model families written by the provider. |
| `schema_owner_key` | Owner key from `tools/schema_object_ownership_manifest.json` or successor manifest. |
| `refresh_row_supported` | Boolean declaring whether row refresh is supported through the facade. |
| `rebuild_incident_supported` | Boolean declaring whether incident rebuild is supported through the facade. |
| `rebuild_after[]` | Provider keys that must complete before this provider when a projection dependency exists; default `[]`. |
| `characterization_refs[]` | Store-backed tests proving row shape, filter/sort/group behavior, refresh behavior, and rebuild behavior for each declared view. |

Provider registration rules:

| Rule | Required behavior |
| --- | --- |
| Determinism | Collect compiled provider descriptors, validate them before serving traffic, and store runtime dispatch ordered by exact `view_schema_id` ascending. |
| Uniqueness | Reject duplicate `provider_key` values and duplicate active `view_schema_id` ownership. |
| Surface coverage | Require exactly one active provider for every required current-profile workbook surface; require zero or one for standardized optional surfaces depending on claimed support. |
| Manifest agreement | Validate each `schema_owner_key` against the schema ownership manifest for every projection schema object family the provider writes. |
| Rebuild graph | Validate every `rebuild_after[]` reference, reject cycles, topologically sort providers, and break ties by `provider_key` then `view_schema_id` ascending. |
| Caller isolation | Callers outside the source owner and the projections facade must not call provider SQL directly. |

Provider ownership matrix:

| Surface family | `view_schema_id` values | Source-owner provider |
| --- | --- | --- |
| Timeline | `cartulary.view.timeline.v2` | Timeline provider. |
| Hosts, identities, indicators | `cartulary.view.hosts.v1`, `cartulary.view.identities.v1`, `cartulary.view.indicators.v1` | Entities/indicators provider. |
| Evidence | `cartulary.view.evidence.v1` | Evidence provider. |
| Notes and coordination artifact surfaces | `cartulary.view.notes.v1`, `cartulary.view.comm_log.v1`, `cartulary.view.handoff.v1`, `cartulary.view.status_review.v1`, `cartulary.view.lesson.v1` | Artifact provider. |
| Optional artifact-backed surfaces | `cartulary.view.findings.v1`, `cartulary.view.investigative_queries.v1`, `cartulary.view.forensic_keywords.v1` | Artifact provider when implemented. |

| Task requests, decisions | `cartulary.view.task_requests.v1`, `cartulary.view.decisions.v1` | Task/decision provider. |
| Parties | `cartulary.view.parties.v1` | TODO: assign current repository source owner before moving party projection SQL. Until then, the party provider remains inside the projections facade. |

Per-provider characterization gate before SQL movement:

| Test area | Required proof |
| --- | --- |
| Projection refresh | Source mutation refreshes the same `view_row_v1` row before and after extraction. |
| Incident rebuild | Full incident rebuild produces byte-equivalent row payloads or explicitly equivalent canonical JSON for every affected `view_schema_id`. |
| Query row shape | Every schema-declared non-technical field appears in `cells`; nulls serialize as `{ "value": null }`; hidden technical fields stay top-level. |
| Sorting | User sort, default-tail expansion, and `record_id asc` tiebreak behavior remain unchanged. |
| Filtering | Filter eligibility, normalization, case behavior, collection-field behavior, and error behavior remain unchanged. |
| Grouping | `group_by` inactive/active behavior and `group_values` remain unchanged. |
| Collection cells | Record refs, party refs, tags, evidence refs, support refs, and artifact-backed collections preserve shape and ordering. |
| Restore | Restore or restore verification rebuilds projections and can open at least one incident and execute at least one built-in workbook query. |
| Import | Import applies through owner create/refresh facades; import dispatcher does not call projections or projection tables directly. |
| Authorization | Provider extraction adds no public route and does not bypass current incident membership or role checks. |
| Telemetry | Operation names and safe projection vocabulary remain bounded and content-safe. |
| Manifest | Provider manifest, if added, and schema ownership manifest agree for every touched projection table family. |
