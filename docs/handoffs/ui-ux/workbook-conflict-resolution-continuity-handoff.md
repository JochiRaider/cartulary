## Reproduction and correction

Before production edits, a focused `WorkbookActiveSurfaceFrame` test held A's resolution, selected B and entered `  Exact B merge  `. It failed because A's completion removed the Recovery region (`.cartulary/test-results/20260926T224908Z-p61230`). The prior component-wide message and submitting flag, together with a completion check that ignored internal conflict selection, explain that failure. Earlier fixture/catalog setup failures were corrected before recording these product reds.

`WorkbookMutationRuntime.beginConflictResolution` now reports synchronous rejection or an admitted typed settlement. It retains the existing write reservation, transaction, endpoint, payload and source-owner projection. A resolution clears a queue entry only when the submitted token still owns that key after awaited refresh; replacement returns `superseded`. Successful server acknowledgement with a failed projection read retains refresh debt, without resending the write.

The resolver keeps only attachment-local attempts and feedback by conflict key and token. Same-frame duplicate activation is guarded before rendering; admitted controls keep their names and keyboard focus with `aria-busy`/`aria-disabled`; the grouped navigator remains usable. An attempt carries a separate revocable presentation intent: submission ID, selected conflict, activation/attachment, authority epoch, interaction generation, grid and viewport. Navigation, keyboard, pointer, scroll, Recovery retarget, Close, authority change and departure retire only presentation effects. The continuation checks eligibility again after mutation/projection and after semantic grid focus, using an abort signal. A stale result cannot clear a newer attempt or present A's feedback as B's. When an internally selected A is removed after its focus intent was retired, Recovery returns to its list; reopening the group exposes B's preserved draft.

This retires the component-wide pending/message and unconditional close/focus completion path. It adds no schema, endpoint, persistence, dependency, batch replay or autosave re-key behavior. Text, atomic, collection and compound-action restrictions, keep-saved versus attributed writes, authorization and record-level reservations remain with existing owners. Rollback is the source change to the resolver and runtime together plus the authored test-family rows; no data migration is required.
