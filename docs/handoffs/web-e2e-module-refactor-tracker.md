### Normative language and tracker requirements

The key words **MUST**, **MUST NOT**, and **MAY** are normative within an authorized refactor execution that adopts this tracker. **MUST** states a condition required for completion. **MUST NOT** states a prohibited condition. **MAY** states a permitted choice that cannot be required by an implementer. Unqualified prose is explanatory. This tracker governs planning, sequencing, evidence, and handoff only; it cannot create, amend, or supersede product, security, contract, or harness behavior. When a requirement below needs an owner change, the owner change MUST be adopted before implementation.

| Requirement ID | Normative requirement |
| --- | --- |
| WEB-E2E-REQ-001 | An implementation MUST apply the authority order in this section, MUST map each changed observable to its adopted owner, and MUST stop with `BLOCKED: owner contradiction` when adopted owners conflict. Draft documents and this tracker MUST NOT authorize behavior. |
| WEB-E2E-REQ-002 | A refactor slice MUST preserve HTTP and WebSocket shapes, authorization outcomes, view-schema identities, row/revision/conflict semantics, projection behavior, selectors, and harness accounting unless the slice is explicitly marked `requires later authorization` and that authorization is recorded. Defaults MUST be explicit at the interface that applies them. |
| WEB-E2E-REQ-003 | Reference Pack list-controller sequencing behavior MUST NOT be added or changed until Core 00 ownership, a Core 01 requirement, Core 04 AC-443 verification text, and Appendix F traceability agree on one adopted algorithm. Existing assertions already owned by adopted Core requirements MAY receive mechanical, behavior-preserving changes after ledger review. |
| WEB-E2E-REQ-004 | Before a Reference Pack assertion is changed, every assertion in `reference-pack.spec.ts` MUST have exactly one assertion-ledger row with the schema and closed values defined in Section 4. An assertion with only draft authority MUST have disposition `blocked` and permitted change `blocked_draft_only`. |
| WEB-E2E-REQ-005 | `apps/web/e2e/**` MUST NOT import from `apps/web/src/**`. Its current allowlist is empty. E2E code MUST consume stable selector functions from `@cartulary/ui-contracts` or page-object-local types and MUST NOT publish or alias private controller types for compatibility. |
| WEB-E2E-REQ-006 | `tools/frontend_visual_fixture_registry.json` MUST be treated as exhaustive for its declared semantic fixtures and design projections only. Registry absence MUST NOT, by itself, classify a committed PNG as drift or an orphan. Registry linkage MAY be `null`. |
| WEB-E2E-REQ-007 | Before any PNG move, refresh, deletion, or accounting change, all committed PNGs MUST reconcile through the Section 4 schema to exact assertion, catalog, scenario, project, and snapshot-template evidence. Filename interpretation MUST NOT establish semantic ownership. `missing_golden` or `ambiguous_mapping` MUST block mutation. |
| WEB-E2E-REQ-008 | Authored owner inputs MUST be changed before their machine projections. Generated roots, generated harness/topology outputs, lockfiles, and snapshots MUST NOT be hand-edited. Authorized generation and snapshot mutation MUST use the Make-owned commands recorded in Sections 7 and 8. |

Finding classifications are closed and have these meanings:

| Classification | Normative meaning |
| --- | --- |
| `must_fix` | The finding blocks refactor completion. The affected slice MUST NOT be declared complete while the finding remains. |
| `should_fix` | The finding remains required unless a later evidence-backed tracker revision changes it to `defer` and names the gate. |
| `defer` | Implementation is prohibited until the named authority or evidence gate closes. |
| `intentional/no_action` | The boundary was reviewed and is closed without a change; later work MUST preserve it unless new owner evidence reopens it. |

S-RP-00 proposes `REQ-01-610A` with this complete browser algorithm. This proposal is non-executable until adopted:

1. Effective request state consists of normalized search, `pack_version_state`, `verification_result`, `active`, effective limit, and a cursor bound to that exact state.
2. A material search or filter change MUST discard the prior cursor and request the first page.
3. Admission of a newer request generation MUST expose the exact pending status `Searching`.
4. Prior rows MAY remain visible while pending only while the caller remains authorized to view them.
5. Only the newest admitted generation MAY replace rows or paging, clear pending state, or provide the current terminal error.
6. A response from an older generation MUST have no visible effect, including when attempted cancellation fails or races.
7. Cancellation MAY be attempted, but correctness MUST be independent of `AbortController`, client support, and cancellation success.
8. No debounce duration is normative. Enter or an equivalent explicit submission MUST immediately admit the newest normalized state.
9. Loss of authentication, `deployment_admin`, extension availability, or deployment authorization MUST clear protected data under the adopted fail-closed behavior.

The owner repair MUST amend Core 00 REQ-00-059's owner matrix, add Core 01 `REQ-01-610A` or an equivalent adopted identifier, amend Core 04 AC-443 so it verifies rather than defines the algorithm, and update Appendix F traceability. Partial adoption MUST leave the sequencing family blocked.
