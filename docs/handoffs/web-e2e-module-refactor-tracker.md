- **Target path:** `apps/web/e2e`

- **Mode:** authorized implementation of the adopted remediation plan.

- **Non-goals:** no product behavior, dependency, lockfile, public Make contract, spec path/title, evidence-class, visual-fixture, or golden-byte change; no hand edits to generated files.
- **Implementation authority:** the analysis-note decisions close RB-001 through RB-005 for behavior-preserving implementation. S-06B requires separate later authority and is not part of this change.

The existence of `apps/web/e2e` is not evidence that `web-e2e` is a durable product-module boundary. Live inspection shows that it is a legitimate Playwright suite and evidence facade, while its support code is also a phase-shaped, mixed-responsibility package. The phase maps and test rows select and account for evidence; they do not define runtime architecture or semantic ownership.

The generic planning framework anticipates a candidate module boundary. ## 3. Module Boundary Diagnosis

The target is a legitimate thin Playwright application/service facade at its composition edges, but the directory as a whole is a mixed-responsibility test package and accidental support-code catch-all. It is transport-adjacent because it drives HTTP/WebSocket/test-control boundaries, mutation-coordinating in its fixture helpers, view/projection-adjacent in its query and refresh support, frontend-controller-adjacent in its page choreography, and grid-adapter-adjacent in its UI assertions. It contains no production persistence implementation and no direct grid-vendor import.
