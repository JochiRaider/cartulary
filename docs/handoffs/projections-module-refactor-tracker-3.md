## 3. Workbook Boundary Diagnosis

There is no `internal/modules/projections/workbook` package. The target contains `workbook_hot.go`, which is a compatibility facade for hot workbook projection tables, not the workbook module itself.

Current `internal/modules/workbook` diagnosis: a legitimate transport-adjacent application facade and mutation coordinator with route-level authorization and query dispatch responsibilities. It owns HTTP routes, request decoding, route authorization, workbook query pagination/envelopes, mutation route shapes, conflict/revision integration, and collaboration publication handoff. It should not be treated as owner of source-record semantics, projection materialization internals, saved-view lifecycle beyond workbook APIs, revision conflict semantics, or WebSocket transport semantics merely because workbook routes trigger them.

Current `internal/modules/projections` diagnosis: a mixture of legitimate thin service facade, view/projection orchestration layer, restore rebuild adapter, and row/query materialization layer. It is not an accidental full workbook catch-all in the current repo because source-domain projection SQL is behind source-owner `projectionprovider` packages, but the central generic query surface remains a boundary risk.
