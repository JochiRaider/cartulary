## 3. Workbook Boundary Diagnosis

The current package is a mixture:

- It is a legitimate thin application/service facade where `routes.go` preserves public workbook HTTP compatibility and translates route-level concerns into internal dispatch.
- It is a view/projection orchestration layer where `store.go` multiplexes timeline, entities, indicators, and generic projection reads into one workbook row contract.
- It is a transport-adjacent adapter where route handlers perform auth, CSRF/session concerns, body decoding, response envelopes, error mapping, telemetry, and WebSocket publishing.
- It is a mutation coordinator where `mutation_store.go` performs direct source writes, revision writes, projection refresh, relationship updates, idempotency, validation, and lifecycle behavior.
- It is a misplaced home for logic that appears owned by other modules or should sit behind clearer facades.
- It is not safe to assume `workbook` is a valid permanent module boundary merely because the directory exists.
