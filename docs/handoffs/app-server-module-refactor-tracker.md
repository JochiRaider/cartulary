## 3. Module Boundary Diagnosis

The package is a mixed-responsibility application facade. It is simultaneously a legitimate thin process facade, a broad application-composition layer, a transport-adjacent adapter location, a persistence-adjacent adapter location, a mutation/publication coordinator, and a test-support exposure point. It contains no frontend controller implementation and no grid-vendor integration.

- Extensions contract major `1` is unconditionally single-active. The

  deprecated.

  development guide; there is no alias, dual read, or automatic marker
  migration.

  identities, modes, startup reasons, and fatal reasons.

  safety, `reference_data` owns the semantic port, and
  `internal/app/referenceassembly` owns the filesystem realization. The draft
  Reference Pack NLSpec is not adopted by this refactor.

  runtime surface is lifecycle-only; test access moves to harness-owned
  resources or owner-specific capabilities.
- Incidents owns the typed final-create-commit boundary. The faulted
  implementation is constructed only in appsupport after test-runtime
  admission; production assembly has no installation surface.
