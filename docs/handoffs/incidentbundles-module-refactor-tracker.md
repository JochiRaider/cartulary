## 3. Module Boundary Diagnosis

The permanent boundary diagnosis is: **keep `incidentbundles` as the thin public owner of whole-incident portability orchestration, while reducing concrete peer coupling and avoiding an unproven broad physical split**. It is a legitimate application/service facade, bundle and projection orchestration layer, mutation coordinator, transport-adjacent adapter, persistence-adjacent adapter, and mixed-responsibility package. It is not an accidental owner of Timeline, Entities, Indicators, Evidence semantics, Links, Saved Views, view-schema semantics, frontend controller state, test-util behavior, imports/tabular ingest, or grid-vendor integration.

### 18.3 External retirement-attestation contract

`IB-R3-S00` adds the public Make target `incident-bundle-v1-retirement-attestation-check` with command ID `cartulary.harness.command.incident_bundle_v1_retirement_attestation_check.v1`. The adopted Testing Harness NLSpec MUST own its public-target registry entry, input matrix, output and failure contract, side effects, and retained artifact identity before task-surface projections change. The target MUST require an explicit command-line-only `ATTESTATION=<path>`; the value MUST NOT be printed, recursively expanded by Make or the shell, or accepted from ambient environment. An unset path fails closed. The target transports the literal path as one redacted argument; the bounded regular-file reader then passes only validated bytes to the document validator. The input is release evidence, not a runtime contract and not a substitute for adopted owner text. Its top-level `schema_id` is exactly `cartulary.incident_bundle_v1_retirement_attestation.v1`.

The schema and validator MUST require, at minimum:

- one shared UTC cutoff date and the retired compatibility snapshot digest;
- the adopting stable release identity and exactly two qualifying subsequent stable v2 release identities, each resolving to a distinct retained passing Make-owned `release-check` run with matching canonical run-manifest, run-summary, target-summary, source, and publication-evidence digests;
- a telemetry interval exactly `[cutoff_date-30 days, cutoff_date)`, zero missing intervals, successful-v1-import count of zero, metric identity, and source evidence digest;
- an operator-inventory cutoff, completeness statement, supported-archive count, v1-required count of zero, and source evidence digest;
- lowercase digests for the retired compatibility snapshot, the three retained release-evidence records and their required artifacts, telemetry evidence, and inventory evidence.

The input schema is closed and contains evidence facts only. Derived eligibility dates, elapsed days, and individual gate states belong exclusively to the deterministic retained result with schema ID `cartulary.incident_bundle_v1_retirement_attestation_result.v1`. The result MUST NOT contain its own digest; after the result is written, the `cartulary.tool_run_summary.v5` extension `cartulary.incident_bundle_v1_retirement_attestation` and the tracker checkpoint record the exact input and result digests. Release identities and dates are allowed. Incident IDs, actor or user IDs, job IDs, object keys, bucket or storage references, archive names, tenant identifiers, raw telemetry series, credentials, free-form operational payloads, and unknown keys are forbidden in input and output. Evidence digests MUST use lowercase `sha256:<64-hex>` form. The validator MUST independently verify retained-run status and digests, date arithmetic, interval continuity, stable-release ordering, release publication evidence, v2 export identity, zero counts, allowed keys, digest shape, and the absence of forbidden identifier-bearing fields; it MUST NOT accept a self-declared `pass` as proof.

On the stable-published path, its adopting release, deprecation date, three-release minimum, 180-day minimum, 30-day telemetry window, and inventory requirement MUST agree with the attestation; a self-reported or stale snapshot digest is not admissible.

The target and its tests are authored through the Testing Harness owner, task-surface owner, verification owners, and generated through Make. If stable publication reopens S01, a future passing run is retained under the standard results root; the tracker records the run root and exact input, result, source, and publication digests, but not the external evidence payload.
