## Findings resolved during remediation

- The retired verifier's signature-labelled checksum path did not authenticate its input. Live imports now use actual Ed25519 authorization and the legacy reader has been removed; historical checksum-labelled data is not promoted to trust.
- Destination root-update attestations incorrectly carried the verification container digest, violating the closed event schema and aborting an otherwise valid rotating cohort. Event-specific construction now keeps the digest only on verification events. The two-version HTTP rotation fixture passes at `20261003T230150Z-p95227` and in later finalization reruns.
- The shared parent transaction treated every lost acknowledgement as indeterminate without consulting a durable success proof. Parent finalization now registers the same exact-success classifier used by ordinary lifecycle operations. The live lost-acknowledgement and rollback cases pass at `20261003T232958Z-p84905`.
- Common failure and cancellation finalization read proofs through the canceled caller context. The shared classifier now uses its bounded independent proof context for every outcome. Success, content/operational failure, timeout and cancellation all retain committed results after caller cancellation; unreadable proof still exercises the fatal path in `20261003T233233Z-p30452`.

- Startup reconciliation previously trusted an imported active selection without rechecking retained content. It now captures coherent revisions, checks immutable bytes and current profile/runtime semantics outside publication locks, and atomically publishes definitive invalidation and fallback. Operational reads and stale observations abort without condemning content. The six-case integration checkpoint passed at `20261004T014402Z-p69801`. The focused review includes the revised capture, historical validation and guarded fallback boundary.
