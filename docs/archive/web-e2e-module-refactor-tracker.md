### Normative language and tracker requirements

The key words **MUST**, **MUST NOT**, and **MAY** are normative within an authorized refactor execution that adopts this tracker. **MUST** states a condition required for completion. **MUST NOT** states a prohibited condition. **MAY** states a permitted choice that cannot be required by an implementer. Unqualified prose is explanatory. This tracker governs planning, sequencing, evidence, and handoff only; it cannot create, amend, or supersede product, security, contract, or harness behavior. When a requirement below needs an owner change, the owner change MUST be adopted before implementation.

### Execution protocol

Slice status uses the closed values `READY`, `IN_PROGRESS`, `DONE`, `BLOCKED`, and `NOT_APPLICABLE`. Exactly one slice MAY be `IN_PROGRESS`; only dependency-complete work MAY be `READY`. A dependency-gated slice is `BLOCKED` with its dependency named, not silently actionable.

At slice start, the execution matrix MUST mark that slice `IN_PROGRESS`. At completion, the execution journal MUST record the owner/specification basis, files changed, substantive decision, compatibility impact, validation commands and run roots, remaining risk, generated or snapshot changes, and next eligible slice. The tracker MUST then mark the slice `DONE`, run `make lint-markdown`, and only after that successful checkpoint mark the next slice `READY`. If adopted owners conflict, the journal MUST record exactly `BLOCKED: owner contradiction` and stop the affected branch.

## 3. Module Boundary Diagnosis

Current diagnosis: `apps/web/e2e` is a mixed-responsibility verification root. It is a legitimate Playwright/Vitest discovery and evidence facade, but it is not a standalone product module and MUST NOT be treated as a permanent `web-e2e` runtime boundary without later adopted owner evidence.

| --- | --- | --- | --- | --- | --- |

  `publicHttpOperation` delegates to the same path and discards the raw

  operation results.

  `support/workbook/refresh.ts` is removed.
