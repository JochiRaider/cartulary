## 3. Module Boundary Diagnosis

Architectural finding: `tools/harness/core` is a legitimate harness core surface, but it is not a confirmed permanent module boundary for product behavior. It is a mixed-responsibility harness package containing public Make wrapper support, retained artifact emission, failure taxonomy, output summaries, runner adapters, finalizer/cache logic, diagnostics, and harness self-tests. It does not currently own workbook orchestration behavior for timeline, projections, revisions, collaboration, imports/tabular ingest, entities/indicators, evidence, links, saved views, view contracts, transport/platform adapters, frontend shell/controller state, or grid-vendor integration.

| Responsibility found | Current location | Correct owner candidate | Keep / move / split / defer | Evidence | Notes |
| --- | --- | --- | --- | --- | --- |
| Public Make wrapper contract helpers | `harness-contract*.mjs`, `public-contract.mjs`, `runner-context.mjs`, Make bindings | Harness public contract core | Keep/split carefully | Testing NLSpec Section 4.1 names these as implementation paths for Make-owned behavior. | Preserve Make target identity, output, artifact, failure, and cleanup contracts. |
