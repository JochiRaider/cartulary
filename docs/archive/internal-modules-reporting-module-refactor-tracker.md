Current source posture:

- Reporting routes remain Core-owned public route-family surfaces implemented by `internal/modules/reporting`.
- Reporting no longer directly reads graph-projection, report-composition, source-record, projection, or owner tables from production reporting files for export materialization; it uses owner facades and owner-local reporting providers.
- Snapshot creation now emits `cartulary.reporting_derivation_profile.v1` and `cartulary.reporting_export_model.v1`. Legacy `cartulary.snapshot_export_model.v3` and `cartulary.export_model.v3` remain explicit read-compatibility identifiers and are not admitted for new release renders.
- Release `output_sha256` is bound to the render-bundle manifest hash. Render bytes are stored as bundle files rather than standalone release columns.
- Redaction emits profile views, token manifests, internal reveal maps, and canonical redaction manifests. Ordinary release resources do not expose rendered bytes, reveal maps, or full manifests.
- Render output is deterministic and bundle-shaped, but still in-process. External Slidev, Chromium, and Mermaid process supervision is future work behind the existing bundle/toolchain/sandbox boundary.
- The previous broad `make check` blocker is closed by the later staticcheck cleanup; the retained successful broad run root is `.cartulary/test-results/20260707T030204Z-p354744`.

Superseded assumptions:
