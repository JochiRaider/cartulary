# Testing Harness Recovery Resource Allocation Register

## Document role

This S4 artifact records allocation, isolation, reuse, collision detection,
release, and parallel-safety rules for shared testing harness resources. It is
evidence only and does not authorize implementation changes.

## Allocation gaps carried forward

- `ss` absence causes port checks to become no-ops in shell helpers; platform behavior is not otherwise specified.
- Scheduler lanes bound harness concurrency but do not prove external Docker, Postgres, object-store, browser, or host OS capacity.
- Reaper scheduling success does not prove reaper completion in S4 static evidence.
- Direct package scripts remain outside Make scheduler/result-root guarantees unless they re-enter wrapper scripts.
