## Classification rules used

| Authority class | S3 meaning |
|---|---|
| `canonical_fixture` | Committed source data or helper constants read by tests or harness helpers. Requires an update rule or `TODO: update_rule_unknown`. |
| `golden_file` | Committed expected output used for exact comparison. Treat as canonical test evidence unless generation authority is proven. |
| `snapshot` | Committed visual or serialized baseline produced by snapshot tooling. Treat as canonical test evidence with explicit update authority required. |
| `derived_report` | Runtime or committed summary/report/log derived from another owner. Non-authoritative unless an entrypoint consumes it for execution, drift, scheduling, duration planning, or investigation. |
| `generated_artifact` | Committed or ignored output produced by generator/update commands. Upstream owner and drift checker must be separate. |
| `temporary_file` | Scratch, temp, runtime-root, env, pid, lock, cache, or build intermediate expected to be disposable. |
| `failure_only_artifact` | Trace, screenshot, stdout/stderr, watchdog, or failure bundle retained only on failure or verbose paths. |
| `reused_across_runs_artifact` | Retained run summaries, baselines, caches, templates, package fixtures, or shared reports reused by later commands. |
| `external_state` | Database, bucket, object namespace, browser profile, process, port, container, or service lease outside git-tracked files. |
