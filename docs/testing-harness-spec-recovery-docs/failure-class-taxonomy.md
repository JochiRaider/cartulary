# Testing Harness Recovery Failure Class Taxonomy

## Document Role

This S5 artifact defines the failure classes used by
`failure-mode-register.md`, lifecycle rows, phase transitions, and partial
completion states. It separates product assertion failures from harness
operational failures and records retryability explicitly.

## Harness Summary Class Crosswalk

Source-observed helper code also uses broad summary classes. S5 keeps those
classes as observed implementation evidence but exposes the more specific
taxonomy below for NLSpec drafting.

| Source summary class | S5 treatment | Evidence |
|---|---|---|
| `test` | product assertion failure unless setup/reporting failed first. | `scripts/lib/tool-output.mjs`; `scripts/lib/failure-taxonomy.mjs` |
| `infra` | harness operational failure, usually setup/service/platform. | `scripts/lib/tool-output.mjs`; `scripts/lib/failure-taxonomy.mjs` |
| `timing` | harness operational failure routed to S6 unless it is only duration-baseline drift. | `scripts/lib/tool-output.mjs`; `scripts/lib/failure-taxonomy.mjs` |
| `artifact` | harness operational failure in report/artifact/accounting production or validation. | `scripts/lib/tool-output.mjs`; `scripts/lib/failure-taxonomy.mjs` |
| `helper` | harness operational failure in wrapper/helper execution. | `scripts/lib/tool-output.mjs`; `scripts/lib/failure-taxonomy.mjs` |

## Taxonomy

| Failure class | Status | Meaning | Detection | Reported where | Exit/report/artifact surface | Retryability | Product vs harness ownership | Cleanup follow-up | Artifact follow-up | Resource follow-up | Evidence status | Notes |
|---|---|---|---|---|---|---|---|---|---|---|---|---|
| `usage_error` | `complete` | Invalid CLI args, missing required flags, or malformed invocation shape. | CLI argument parsing before work starts. | stderr usage text; sometimes bounded helper diagnostic. | exit `2` in source-observed shell/Node/Go CLIs. | `no` until caller fixes invocation. | harness operational. | none. | none. | none. | `observed` | Applies to phase wrappers, schedulers, reset script, runner, and testservices. |
| `configuration_error` | `complete` | Required tool, binary, env, config file, manifest, path, or runtime default is missing or invalid. | setup/config validation, missing binary checks, manifest/schema checks, env validation. | stderr, scheduler summary when context exists, target summary if wrapper reaches reporting. | usually exit `1`; missing `TEST_SERVICES_BIN` in `cartulary-runner.mjs` exits `2` for that wrapper usage/config boundary. | `no` until configuration changes. | harness operational. | partial setup cleanup if resources already started. | yes when partial run dirs/logs exist. | maybe, if services started before config failure. | `observed/source_limit` | Env precedence and public env contract route to S8. |
| `preflight_error` | `complete` | Docker/testcontainers/platform or suite preflight fails before managed service startup. | testservices preflight returns failure before child work. | service-scope diagnostics, suite failure line, scheduler/target summary when wrapped. | exit `1` from testservices preflight path; child command not started. | `conditional` after environment/platform/resource issue is fixed. | harness operational. | usually no managed-service cleanup, but diagnostics should record state. | yes for service-scope diagnostics. | maybe if preflight has external side effects; source-limited. | `observed/source_limit` | Live Docker failure examples were not run. |
| `service_start_error` | `complete` | Postgres, MinIO, Compose, backend, frontend, or other harness service fails to start. | start command failure, process early exit, testcontainers attempt failure, Compose state failure. | stderr/logs, service-scope file/events, browser backend/frontend logs, scheduler/target summaries. | usually exit `1`; target/scheduler summaries classify failure. | `conditional`; retries may help only for transient environment/service conditions. | harness operational. | required for any partially-started service. | yes for logs/service events. | yes; service/container/process/port cleanup follow-up possible. | `observed/source_limit` | Testservices has source-observed retry attempts; runtime exhaustions not observed. |
| `service_readiness_timeout` | `complete` | Service process starts but readiness endpoint/health condition is not met before timeout. | readiness loop exhaustion or child process dies while waiting. | stderr readiness diagnostic, recent logs, scheduler/target summaries. | usually exit `1`; browser wrappers retain logs and stack files. | `conditional`; depends on slowness, resource pressure, or product/service bug. | harness operational unless readiness endpoint itself is a product contract under test. | yes; started process/service must be stopped. | yes for logs/stack/service-scope files. | yes; ports/processes/containers may remain if cleanup fails. | `observed/source_limit` | Timing thresholds and cleanup strength route to S6. |
| `fixture_error` | `complete` | DB, bucket, template, reset, worker-admin, stale janitor, or fixture budget operation fails. | fixture helper returns non-zero/error, reset validation fails, janitor reports unsafe/failed candidate, fixture budget check fails. | stderr, reset response/status files, service-scope diagnostics, scheduler/target summaries. | usually exit `1` or failed scheduler summary. | `conditional` or `unknown`; reset/cleanup authority may be undecided. | harness operational, with possible product-side state side effects for reset route. | yes when DB/bucket/template/service state may be partial. | yes for reset/service fixture diagnostics. | yes for stale DB/bucket/container/process resources. | `observed/source_limit` | Reset authority and janitor bounds route to S8. |
| `resource_conflict` | `complete` | Port, scheduler lane, DB/bucket name, process, lock, external cache, or host/service capacity conflict. | port probe, resource override validation, scheduler capacity policy, fixture naming collision, lock/cache error. | stderr/logs, scheduler events/summary, target summaries. | usually exit `1`; exact code is command-specific. | `conditional`; retry may help if conflict clears, no if config is inherently conflicting. | harness operational. | maybe; partially-started resources may need cleanup. | yes when conflict artifacts/logs are retained. | yes; resource release/follow-up is central. | `observed/source_limit` | Logical scheduler lanes are not proof of concrete host capacity; S6 owns. |
| `test_assertion_failure` | `complete` | Product behavior assertion fails after harness setup succeeds. | Go/Vitest/Playwright/test runner exits non-zero and summaries classify as `test`. | test runner logs, phase/target summaries, Playwright/Vitest/Go reports, scheduler summaries. | child exit status is propagated through wrapper or summarized as failed target/scheduler. | `no` by default; `conditional` only if a separate flake/rerun policy is documented. | product assertion failure owned by relevant product/test area. | cleanup only for harness resources used by the test. | yes for failure diagnostics/traces/screenshots/logs. | maybe, if service/browser resources were active. | `observed/source_limit` | Must not be merged with harness operational failures. |
| `timeout` | `complete` | Command, test, readiness, lock, cleanup, or watchdog exceeds an enforced deadline. | readiness loop exhaustion, watchdog JSON, command timeout, scheduler/tool timeout, cleanup timeout. | stderr/logs, watchdog JSON, scheduler/target summaries, failure-only artifacts. | usually exit `1` or tool-specific non-zero; watchdog schema observed for Vitest. | `conditional` or `unknown`; depends on whether timeout is environmental, capacity-related, or deterministic. | harness operational unless underlying test assertion is explicitly timeout-based product behavior. | yes, especially for started services/processes. | yes for logs/watchdog/failure bundle. | yes; timed-out processes/services may remain. | `observed/source_limit` | Timeout and interrupt cleanup are S6. |
| `cancelled_or_interrupted` | `complete` | User interrupt, CI cancellation, parent death, signal, or abrupt runner abort. | traps/signals/source paths or external interruption; not exercised by S5. | partial logs/summaries if emitted before interruption; shell/runner signal status otherwise. | exit status source-limited and command-specific. | `unknown`. | harness operational unless cancellation is external. | yes; cleanup on signal/parent death is unresolved. | yes if partial artifacts remain. | yes; active processes/services/resources may remain. | `source_limit` | Parent-death and interrupt behavior route to S6. |
| `cleanup_error` | `complete` | Cleanup returns non-zero, leak check fails, reaper scheduling fails, or cleanup completion is unverifiable. | cleanup status, finalizer failure, service-scope diagnostics, browser cleanup path, scheduler finalizer result. | stderr/logs, service-scope file, scheduler summary, target summary, cleanup status artifacts. | usually exit `1` or failed scheduler/target summary; child exit may still be recorded separately. | `conditional`; retry may clean stale resources but could be unsafe without authority. | harness operational. | yes. | yes for cleanup diagnostics. | yes; resource leak/stale artifact follow-up likely. | `observed/source_limit` | Best-effort versus guaranteed cleanup is S6/S8. |
| `unsupported_platform` | `complete` | Required or assumed platform/tool behavior is unavailable. | missing tool checks, shell command failure, Docker/Compose/browser/runtime unavailability, OS utility absence. | stderr/config diagnostics, target/scheduler summary if wrapper reaches reporting. | command-specific; usually exit `1` or usage/config failure. | `no` until environment changes or support profile is expanded. | harness operational/authority-required. | maybe if failure occurs after partial setup. | yes for diagnostics. | maybe if partial resources started. | `source_limit` | Supported platform profile is an S8 decision. |
| `authority_required` | `complete` | Observable behavior exists but cannot be made normative without maintainer decision. | S5 detects conflicting/ambiguous ownership or missing normative source. | recovery docs, ambiguity/source-limit registers, sometimes runtime output if command is used. | `n/a` as runtime class unless a command also failed. | `n/a`. | maintainer/harness authority decision required. | depends on associated behavior. | depends on associated behavior. | depends on associated behavior. | `maintainer_decision_required` | Reset route, package scripts, local-dev services, public env contracts, janitor bounds, platform profile, and external caches. |
| `manifest_or_accounting_mismatch` | `complete` | Declared manifests, expected target artifacts, accounting classes, or generated ledgers do not match observed/committed outputs. | artifact assertion, drift checker, ledger checker, accounting classifier, baseline coverage checker. | stdout/stderr drift diagnostics, target/run/tool summaries when wrapped. | usually exit `1`; summary class generally `artifact` or `helper`. | `no` until source/generated artifact mismatch is fixed. | harness operational. | no service cleanup unless command ran service work first. | yes; mismatched artifacts are the failure subject. | no, except stale external caches when involved. | `observed` | Kept separate from product assertion failures. |
| `unknown_failure` | `complete` | Failure cannot be classified with available S5 evidence. | catch-all exception, unrecognized exit, stale/unselected artifact, unavailable failure bundle. | stderr, partial summary, source-limit row, or retained artifact if selected. | command-specific; often exit `1` in catch blocks. | `unknown`. | unknown until evidence is selected. | unknown. | yes if artifacts exist but schema/provenance is unclear. | unknown. | `source_limit` | Must be registered instead of inferred. |

## Checklist Support

| Field | Value |
|---|---|
| Status | `complete` |
| Blockers | Controlled failure examples and provider CI annotations were not available; runtime-only timeout/interrupt/cleanup cases were not exercised. |
| Findings | Every required class has detection, reporting location, exit/report/artifact surface, retryability, ownership, and cleanup/artifact/resource follow-up. |
| Source limits | `preflight_error`, `service_start_error`, `service_readiness_timeout`, `fixture_error`, `timeout`, `cancelled_or_interrupted`, `cleanup_error`, `unsupported_platform`, and `unknown_failure` retain source-limited aspects. |
| Ambiguities | `authority_required` covers reset route, package scripts, local-dev services, public env contracts, stale janitor bounds, platform profile, and external caches. |
| Handoff notes | S6 should probe source-limited runtime classes; S8 should resolve authority-required classes before NLSpec turns them into normative requirements. |
| Evidence status | Rows use `observed`, `observed/source_limit`, `source_limit`, or `maintainer_decision_required`. |
| No-change confirmation | This file records recovery documentation only and does not alter harness behavior. |
