# Testing Harness Recovery Sequencing Assumption List

## Document role

This S2 artifact records command ordering, nesting, parallelism, and shared-state
assumptions discovered while mapping harness entrypoints. It is source material
for later artifact, service, lifecycle, hazard, and failure-mode recovery.

Rows intentionally distinguish observed declarations from runtime behavior that
was not exercised during S2.

## Entry/exit ordering summary

| Area | Current observed ordering | Risk or gap |
|---|---|---|
| Local fast loop | Local unit/typecheck/frontend unit work precedes service-backed fast scheduler. | Runtime success/failure not observed in S2. |
| Full test loop | Local work precedes full service-backed scheduler with backend and browser leaves. | Browser reset and shared state lifecycle deferred. |
| Developer gate | Check scheduler owns readiness fanout, static checks, service-backed work, browser work, and build-related checks. | Exact failure-mode taxonomy deferred. |
| Release gate | Developer gate and extended harness run before release artifacts and build aggregate. | Release artifact authority deferred. |
| Browser evidence | Web E2E stack starts before batch groups and tears down after child command/session stop. | Port/process cleanup and timeout behavior deferred. |
| Service-backed evidence | Testservices wrapper starts suite services before scheduler child command unless suite already active. | Service readiness, lease, cleanup, and reaper behavior deferred. |
