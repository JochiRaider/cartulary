## Classification rules used

| Class | S4 meaning |
|---|---|
| `provisioned_service` | The harness starts a process, container, emulator, route, or stack and owns at least one stop or cleanup path. |
| `external_service` | The harness requires a service, daemon, network, or tool runtime that it does not fully own. |
| `database` | A logical Postgres database, template, clone, package DB, transaction, migration scratch DB, or web E2E DB. |
| `container_or_emulator` | Docker Compose service, testcontainer, object-store emulator, or suite-service-owned container. |
| `browser_profile` | Playwright state directory, storage state, worker admin manifest, browser context, browser page, or session state. |
| `shared_resource` | Port, socket, file lock, temp path, runtime root, process group, worker lane, scheduler lane, cache, bucket, prefix, or object namespace. |
| `secret_or_network_assumption` | Credentials, localhost binding, Docker endpoint, object-store keys, config-derived DSNs, or network availability. |
| `unsupported_platform_behavior` | Platform behavior proved or left unknown by source; use `TODO: platform_unknown` where not proved. |
