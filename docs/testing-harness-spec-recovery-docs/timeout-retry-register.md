# Testing Harness Recovery Timeout Retry Register

## Document role

This S6 register records source-observed sleeps, polls, waits, retries,
timeouts, lock waits, readiness checks, cleanup windows, watchdogs, and
debounce/watch surfaces relevant to the testing harness. Unless a row says
otherwise, values are static source evidence and do not prove host-specific
timing, cleanup completion, retry exhaustion, signal handling, or parent-death
behavior.

## Timing classification rules

| Type | S6 meaning |
|---|---|
| `fixed_sleep` | An unconditional sleep or delay before rechecking or continuing. |
| `polling_loop` | A repeated condition check until success or deadline. |
| `retry` | Re-execution of an operation after a classified failure. |
| `timeout` | A bounded operation with deadline or configured maximum duration. |
| `cleanup_wait` | A bounded cleanup, process-exit, port-release, or signal wait. |
| `readiness_check` | A probe whose success allows later work to start. |
| `lock_wait` | A bounded lock-acquisition loop. |
| `watchdog` | A monitor that kills or reports a child when expected output is absent. |
| `watch/debounce` | Delayed progress/watch behavior; no harness debounce contract was found outside grouped UI test helper surfaces. |
